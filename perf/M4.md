# Running the M4 perf cells

On the Apple Silicon Mac, from the repo root:

```bash
# 1. Dense BLAS vs Accelerate (fills perf/m4-blas.md)
just perf-cell m4 blas

# 2. Dense LAPACK vs Accelerate (fills perf/m4-lapack.md)
#    Runs lapack_compare (sonium vs Accelerate) + direct-solver-perf.
just perf-cell m4 lapack

# 3. Sparse matrix: CPU SpMV roofline + effective iterative BW (fills perf/m4-sparse-matrix.md)
just perf-cell m4 sparse-matrix

# 4. Dense solvers: LU factor+solve vs Accelerate (fills perf/m4-dense-solvers.md)
just perf-cell m4 dense-solvers

# 5. Sparse solvers + preconditioners incl. PETSc KSP (fills perf/m4-sparse-solvers.md)
#    Build the PETSc reference first (needs PETSc with Hypre; then from FFI dir):
#      export PETSC_DIR=/path/to/petsc PETSC_ARCH=arch-darwin-c-opt
#      cd crates/sonium-solvers/benches/ffi && ./build_petsc.sh
#    Then:
ITERATIVE_PERF_PETSC="$PWD/crates/sonium-solvers/benches/ffi/petsc_reference" \
  just perf-cell m4 sparse-solvers
```

Then commit `perf/m4-*.md`.

(Each `perf-cell` run executes its benches itself; the standalone
`just bench-lapack`, `bench-sparse-cpu`, `bench-gmres-cuda`,
`bench-petsc-run` recipes are for iterating without re-rendering.
`just perf-m4` runs all five cells at once.)

Threading: Sonium uses its default thread pool on macOS; Accelerate
manages its own threads (`VECLIB_MAXIMUM_THREADS` caps it). If the box
is busy, prefer a quiet window — single-thread ratios are the stable
comparison (see root `PERF.md` methodology).
